## 当前结论与原因

1. **裁定约束已补，但语义能力尚未得到整体验收。** [evidence_reviewer.py](../../backend/src/novelty_agent_framework/agents/evidence_reviewer.py)第 303–305、1135–1171 行现有同一 Work 全特征支持检查。历史“不安全裁定只靠 prompt 防守”的描述已过时；引用是否真的支持机制仍需材料对照，代码门控不等于语义真值。
2. **候选消费和上下文仅部分处理。** 检查点、Reader 重用、状态投影已实现，但默认关闭，且状态投影保留全部聊天历史；重复结果仍可能重复进入上下文。详见 [02](02_Harness与上下文管理.md)。
3. **恢复策略已超出单纯卡数路由，但仍漏掉卡数达标的 Reviewer 技术失败。** [recovery_policy.py](../../backend/src/novelty_agent_framework/core/recovery_policy.py)第 30–33 行先排除非数量缺口、非 semantic_evidence 的点，使第 54–59 行的技术错误处理不可达。详见 [03](03_Runtime_Token_错误码与Reviewer.md)。
4. **当前仍不能宣布整套能力已验证。** [最新整流程归档](../experiments/20260928_arxiv_web_full_workflow.md)记录 NP-1/3 覆盖拒绝、NP-2 引用失败、NP-4 材料不足，且 NP-2 不在恢复列表。任务书中的“无卡”不是永远没有进展：后续运行已经形成卡片；但产卡与正确裁定须分开。

## 补充：抽取前的信息边界仍然很窄

位置：[point_extractor.py](../../backend/src/novelty_agent_framework/agents/point_extractor.py)第 30–31、67–103 行。

`PaperDigest` 正文只给开头 2,000 字符，加最多三处匹配 `(?:主要|核心)贡献(?:可以)?总结` 的 1,200 字符片段；英文 Contributions、其他中文表述及更后面的机制可能没有进入输入。这是当前代码可确认的覆盖限制，不能仅靠保守去重修复，也不能把具体漏项全部归为模型能力。

[point_coverage.py](../../backend/src/novelty_agent_framework/core/point_coverage.py)第 176–187 行已明确账本范围仅为给定 digest 和已记录候选，`semantic_coverage_verified`、`unseen_full_text_coverage_verified` 均为 false。尚缺“论文原文→贡献/必要特征→候选→下游”的人工对照，不能把候选字面保留率称为贡献召回率。

### 抽取遗漏的原因进一步缩小

[抽取原始轨迹](../experiments/20260930_issue_audit_live/runs/0001/MF2033k6lC/runtime/run-480a9f6d8a59475f860887c3a6f45324/diagnostics/point_extraction_trace.json) 的 digest 已含 GSAERU 图自编码/重构误差，以及 DSGNN 注意力层、梯度同步；generation.raw_candidates 已缺失这些具体机制，final_points 同样缺失。因此这几个漏项发生在候选生成阶段，不是候选被去重删除，也不能单归为摘要截断。RNN、Count-Min Sketch、最小堆则有保留。

另有正面证据：模型提议将 DSGNN 当 GSAERU 重复项删除，但 conservative_dedup 的字面覆盖防护拒绝了该提议，三点均保留。[字段定位](../experiments/20260930_issue_audit_live/workflow-analysis.json) 是辅助核查，不是完整人工金标或全文贡献召回率。

静态风险中的截取边界仍成立，但真实结果表明还存在“输入已包含、生成未保留”的独立问题。无需改生产代码即可定位两者。
