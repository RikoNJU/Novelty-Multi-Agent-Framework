## C-01：关闭 debug 会关闭全局调用上限（P1，代码确认）

位置：[runtime_artifacts.py](../../backend/src/novelty_agent_framework/core/runtime_artifacts.py)第 275–290、347–350、398–399、1116–1119 行。

Provider 预算保留函数在 `enabled=false` 或无 run_dir 时直接返回；模型记录函数也先返回，后面的 max_model_calls 检查不会执行。current_runtime_artifacts 甚至不向工具返回 disabled manager，因此工具绕过这个全局预算入口。任务级 Harness 上限仍在，不等于跨任务、跨轮次和物理请求上限仍在。

原因：安全政策和可选记录器绑定。任务书 T19“关闭记录不关闭预算”的要求没有满足。独立 ModelClient 上下文准入仍可能生效，不能把此发现扩大为所有校验均失效。

## C-02：Web、脚本预算尚未共享单一政策（P1）

[workflow_service.py](../../backend/src/novelty_agent_framework/services/workflow_service.py)第 179–185 行只有 `run_model_budget_rmb` 非空才激活 RunModelBudget；否则单独传入的 run_model_max_attempts 不由该账本执行。开启时又要求模型有价格、按 UTF-8 字节预留，见 [03](03_Runtime_Token_错误码与Reviewer.md)。

Runtime 自己也有模型/Provider 上限，且受 debug 开关影响；二者不是统一预算账本。typed config/同一模型 alias 的接线正确，不足以证明三个入口的资源控制完全相同。未复现实付或 Web 请求，只确认这些分支和条件。

## C-03：安装包仍依赖源码仓库布局（P1，新增核查）

位置：[pyproject.toml](../../pyproject.toml)第 11–22、36–45、47–48 行；`config/factory.py`、多处 agents 导入 `backend.env`，诊断导入 `scripts.*`。

- setuptools 只从 `backend/src` 发现包，`backend/env` 和顶层 `scripts` 不在发现根下。源码环境的 pytest `pythonpath=["backend/src", "."]` 会掩盖这个差异。
- 运行路径直接使用 httpx（例如 Provider 和 failure_classification），但 pyproject 中 httpx 仅列为 dev extra；干净安装基础包不保证获得它。
- 默认配置 loader 读取 `config/agents/*.json`，package-data 仅显式列 `config/*.json`，没有覆盖子目录的明确规则。是否因其他构建收集机制被带入需检查真实 wheel，当前不能保证。
- `experiment.py` 第 21 行从 `__file__.parents[4]` 推导项目根，源码和快照采集依赖仓库目录关系。

结论是“打包声明与运行依赖不闭合”的静态风险，**没有声称本轮 wheel 安装失败已实测**。若用户希望确认干净安装行为，需要另行同意隔离构建/安装实验。
