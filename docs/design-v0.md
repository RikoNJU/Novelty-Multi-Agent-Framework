# 论文查新 Multi-Agent 初始框架 V0

## 1. 设计目标

本系统围绕论文创新性开展查新，通过多个 Agent 并行检索和阅读相关文献，为论文评审提供有文献证据支撑的创新性判断。

系统主要完成：

- 提取论文的研究内容和查新点；
- 检索并阅读相关文献；
- 比较已有工作与被评论文的重合和差异；
- 识别缺失的关键文献和实验 Baseline；
- 检查参考文献的真实性和完整性；
- 生成能够输入原论文评审系统的查新报告。


## 2. 设计思路

查新任务需要检索和阅读大量外部文献，适合由多个 Agent 并行处理。本方案让每个文献调研 Agent 完整处理一篇或一组候选文献，避免破坏文献内容的完整性。

系统采用“总—分—总”结构：

```text
总：理解被评论文并规划查新任务
        ↓
分：多个文献调研 Agent 并行检索、阅读和比较
        ↓
总：汇总文献证据并形成查新结论
```

## 3. 总体架构

![论文查新 Multi-Agent 总分总流程图](../assets/workflow.svg)

主流程为：

```text
被评论文
    ↓
Novelty Coordinator
    ↕
Literature Research Agent Pool
    ↓
Novelty Coordinator 汇总
    ↓
论文查新报告
    ↓
原论文评审系统
```

Coordinator 在系统中是一个全局模块，负责查新开始时的任务规划和文献调研完成后的证据汇总。多个 Research Agent 作为并行子 Agent，与 Coordinator 进行任务下发和证据回传。

## 4. Agent 职责

| Agent | 核心职责 | 不负责内容 |
|---|---|---|
| Novelty Coordinator | 理解论文、提取查新点、规划检索任务、分配文献、汇总证据、生成查新报告 | 不独自完成全部候选文献的检索和阅读 |
| Literature Research Agent | 检索和阅读指定文献，提取主要贡献，比较重合点与差异点，返回文献证据 | 不独立生成论文最终创新性结论 |

文献搜索、全文获取、元数据核验和引用匹配可以设计成属于 Agent 可以调用的工具，也可以单独设计成 Agent 完成相关任务。

## 5. 工作流程

### 5.1 总：查新规划

Novelty Coordinator 读取论文正文和参考文献，概括研究问题、技术路线和创新主张，并将其整理成可检索、可比较的查新点。

该阶段形成：

- 论文研究内容摘要；
- 查新点及其原文依据；
- 中英文关键词和检索方向；
- 需要调研的文献任务。

### 5.2 分：并行文献调研

Coordinator 将查新任务分配给多个 Literature Research Agent。不同 Agent 负责不同查新点，在相关文献库中检索此主题获得相关候选文献并进行分析。

每个 Research Agent 需要：

1. 检索或读取指定候选文献；
2. 提取文献的研究问题、方法和主要贡献；
3. 比较候选文献与目标查新点；
4. 标记技术重合点和差异点；
5. 判断该文献是否属于关键相关工作或必要 Baseline；
6. 返回可追溯的原文证据。

### 5.3 总：证据汇总

Coordinator 汇总所有 Research Agent 的结果，完成跨文献比较，并形成：

- 各查新点的创新性判断；
- 与已有工作的主要重合和差异；
- 缺失的关键文献；
- 缺失的实验 Baseline；
- 错误、虚假或无法验证的引用；
- 检索范围、证据缺口和结论置信度。

如果某个查新点证据不足或不同 Agent 的判断冲突，Coordinator 可以针对该查新点发起补充检索，而不重新执行全部任务。

## 6. 最低数据接口

初始框架只规定三个核心数据对象，具体字段和存储方式由实现人员确定。

开发人员可以根据开发需要和功能实现需要设定更多的数据对象。

| 数据对象 | 最低内容 |
|---|---|
| Novelty Brief | 论文研究内容、查新点、技术特征、关键词和调研任务，由 Novelty Coordinator 输出|
| Evidence Card | 候选文献信息、主要贡献、重合点、差异点、证据位置和置信度，由 Literature Research Agent 输出|
| Novelty Report | 查新结论、关键证据、缺失文献、缺失 Baseline、引用问题和检索局限，由 Novelty Coordinator 输出|

所有进入最终报告的重要结论都必须关联可追溯的文献来源。只有模型判断、没有文献证据的内容不能直接作为创新性结论。

## 7. 查新结论

查新系统不使用“世界首创”“绝对原创”等超出检索能力的表述。建议采用以下结论类型：

- 创新性证据较强；
- 部分创新；
- 创新性较弱；
- 证据不足。

每项结论应同时说明主要支持证据、相反证据和当前检索范围。

## 8. 必须遵守的架构约束

实现人员可以自由选择开发框架、模型、数据库、状态结构和调度方式，但不得改变以下原则：

1. Coordinator 负责组织与汇总，不包办全部文献阅读；
2. Research Agent 按文献调研任务并行，不按细碎能力过度拆分；
3. 每个 Agent 应尽可能完整理解自己负责的候选文献；
4. 最终创新性结论由全局视角统一形成；
5. 每条重要结论必须具有可追溯文献证据；
6. 证据不足时必须明确说明，不能由模型补全事实；
7. 输出结果必须能够被原论文评审系统读取。

## 9. V0 预期结果

第一版只需要证明以下闭环能够运行：

```text
输入论文
→ 提取查新点
→ 并行调研相关文献
→ 生成结构化文献证据
→ 汇总创新性结论
→ 输出查新报告
```
