# 论文查新 Multi-Agent 框架 —— 开发内容

> 提交范围：模型调用层、配置装配、工作流、论文处理模块、查新点提取模块、测试版持久化
> 当前状态：2026.8.8提交；全量测试 121 passed / 6 skipped（live 除外）

---

## 一、概述

本项目从“单模型 Demo 骨架”演进为**配置驱动的多 Agent 框架**，已打通
`PDF → paper.json → 查新点提取 → 任务分配 → 并行调研 → 证据校验 → 查新报告`
的完整链路。本阶段交付三块核心能力：

1. **模型调用层**：按角色配置不同模型、支持多模态（OCR）、版本化提示词渲染；
2. **论文处理模块**：PDF 文本化（文本层优先 / DeepSeek-OCR 兜底）→ 章节切分 → 输出工作流兼容的 paper.json；
3. **查新点提取模块**：两步 Agent（增量生成 + 判定式去重审查），测试版落盘。

模型约定（测试阶段）：文本 LLM 统一 `deepseek-ai/DeepSeek-R1-0528-Qwen3-8B`，
OCR 使用 `deepseek-ai/DeepSeek-OCR`。

- 多模态为 OCR 前置能力，OpenAI vision 格式（`image_url` + `text`），硅基流动等兼容平台可直接使用。

## 四、工作流改动（重点）

### 4.1 图结构

原图：

```text
START → plan → parallel_research → validate_evidence → assess_coverage
        ↑                              └─ 补检：plan_supplement → parallel_research
        └─ 充足：synthesize_report → END
```

现图：

```text
START → extract_points → plan → parallel_research → validate_evidence → assess_coverage
                          ↑                          └─ 补检：plan_supplement → parallel_research
                          └─ 充足：synthesize_report → END
```

### 4.2 语义变化

- 新增 `extract_points` 节点：`build_paper_digest(state["paper"]) → point_extractor.extract(...)`，结果写入 `state["novelty_points"]`；
- `coordinator.plan()` 从“提取 + 任务分配”**收敛为只做任务分配**（签名改为 `plan(paper, *, points, attempt)`），brief 的 summary/problem/keywords 由 paper 字段确定性装配；
- `NoveltyState` 新增 `novelty_points`；`NoveltyWorkflowServices` 新增 `point_extractor`（缺省 `DemoPointExtractor`，仿 validator 缺省模式，现有构造不破坏）；
- 补检回路（`assess_coverage → plan_supplement → parallel_research`）保持不变，查新点在首轮提取后全程稳定。

## 五、论文处理模块（processing/）

新增 `PaperPage` / `PaperDocument` / `PaperDigest` schema 与 `PaperProcessor` 协议，实现：

| 模块 | 职责 |
| --- | --- |
| `textify.py` | PyMuPDF 文本层提取 + 质量门（平均字符数达标且低字符页 ≤30%）；不达标降级 200 DPI 逐页渲染 → DeepSeek-OCR 多模态识别 → 拼接 `# Page N` 分页文本 |
| `normalize.py` / `clean.py` | OCR 剥 `<\|ref\|>` / `<\|det\|>` 元数据、修重复；文本层去页眉页脚、连字符接续、竖排标题归一；通用空白/页码清洗 |
| `sections.py` | **链式切分 8 章节**（摘要/关键词/引言/方法/结果/讨论/结论/参考文献），终点=下一节起点；关键词页边界；参考文献延伸至文末；缺节记 `parse_warnings`；摘要失败回退首页 |
| `title.py` | 标题提取：文本层字号信号 + 跨行合并，失败走 R1 兜底 |
| `paper_processor.py` / `cli.py` | 编排 `process()` → `PaperDocument`，`to_paper_input()` → `PaperInput`；CLI 输出 `<stem>.json`（工作流兼容），富结构接口保留但不落盘 |

已知实测结论：

- OCR prompt 用“简单版”（识别全部文字输出 markdown）稳定；曾尝试加入“标题用 ##、不要输出坐标标记”等约束导致模型异常，最终由 normalize 负责清洗标记；
- 参考文献跨页时链式切分曾误截断，已固定“参考文献至文末”，实测 91 条完整提取。

## 六、查新点提取模块（agents/ + workflows/ + prompts/）

### 6.1 两步 Agent（`agents/point_extractor.py`）

- `build_paper_digest(paper)`：abstract + english_abstract + keywords_zh/en + claimed_contributions + full_text_excerpt（从摘要标题起取前 2000 字符，带截断标记，跳过封面）；**暂不提供参考文献**（测试结论：去掉后行为无显著变化，保留配置项）；
- 生成步：单次 ≥3 条直接使用（不合并，**截断至 3 条**，与"输出 3 个查新点"的需求对齐）；不足则**增量重试 ≤3 次**——每次把已生成查新点喂回提示词，要求补充不同且不重复的条目使总数达到 3 条；3 次后合并去重；
- 审查步：**判定式去重**——模型只输出 `{"delete_indices": [...]}`，代码按编号删除后原样保留其余（不允许删空），再重排 `NP-1..NP-n`、上限 3 条。

### 6.2 提示词（用户可自行编辑）

- `prompts/extractor/extract_points.md`：强制“必须输出 3 个查新点”，变量含 `digest_json` / `existing_points_json` / `previous_brief_json` / `attempt` / `point_schema`；
- `prompts/reviewer/review_points.md`（v2）：判定式，只输出删除编号，变量含 `points_json` / `delete_schema`。

### 6.3 为什么最终采用“判定式审查”

真实模型实测：生成步稳定产出 3 条（GSAERU / DSGNN / 性能点），但“重写式去重”审查会把 3 条合并成 1 条；
改为“只判编号、代码删除”后，3 条完整保留。**审查不再重写/合并任何内容**。

## 十二、Research Agent 真实检索编排（2026.8.8 追加）

> 里程碑：M1 arXiv 工具与两层检索 → M2 Agent 编排与装配 → M3 本文档。
> 默认配置 `tools.arxiv.enabled=false`，未启用时 Research Agent 保持原单次模型调用路径，行为与旧版一致。

### 12.1 当前算法逻辑

**数据流（工具启用时）**：

```text
ResearchTask + PaperInput
  → 种子检索（paper 级，按 paper_id 缓存一次）
      ├─ 参考文献：规则提取标题 → ti:"标题" 检索 → token Jaccard ≥ 0.6 校验
      └─ keywords_en：all:"关键词" 检索
  → 扩展检索（task 级，按查新点英文表述）
      ├─ abs:"claim_en"（≤100 字符）
      ├─ abs:"f1" AND abs:"f2"（双特征组合）
      └─ abs:"f_i"（单特征兜底）
  → merge_candidates：按 document_id 去重、标记 cited_by_paper（种子=True / 扩展=False）、
    打分 = 2×多查询命中数 + token 重合度 + 近3年 0.5，截断 top_n=8
  → 候选证据包：full_text_tool.fetch（None 退摘要）+ metadata_tool.resolve（None 退 SearchHit 字段）
  → 模型基于候选文献比较 → EvidenceCard
  → 绑定校验：task_id/novelty_point_id 匹配、sources 的 DOI/URL 必须命中候选包、
    cited_by_paper 由代码覆盖（不信任模型）；未绑定卡片丢弃
```

**关键设计点**：

- 论文输入改传**摘要视图**（`_paper_model_view`：title/abstract/english_abstract/keywords/claims/引用前 15 条/正文 excerpt ≤5000 字符），不再全量塞 `full_text`；
- 128K 上下文预算：论文摘要视图 ~10K tokens + 候选包 ~7K + schema/task ~3K，总输入 ~23K，余量充足；
- 无工具降级：`search_tool is None` 时走原单次模型调用路径（既有测试不破）；
- 检索/取文/解析任一失败按候选级降级（None/空集），不中断整体任务；候选为空时返回 `[]`，由工作流补检轮兜底；
- arXiv 三工具共用 document_id 约定（ID 去 `v<n>` 版本后缀），标识自洽。

**配置**（`settings.example.json` → `tools.arxiv`）：`enabled`、`min_interval`（3s 限流）、`timeout`、`max_retries`（仅 5xx）、`candidate_limit`（8）、`candidate_excerpt_chars`（2000）、`paper_excerpt_chars`（5000）、`title_similarity_threshold`（0.6）、`max_reference_searches`（15）、`keyword_limit`（5）。

### 12.2 未来开发方向（本期不实现，仅记录）

**按查新点类型路由**：
- `NoveltyPoint` 增加 `point_type`（默认 `general`，向后兼容），提取提示词让模型分类；
- 新增 `RoutingResearchAgent`（实现同一 `LiteratureResearchAgent` 协议）：注册表 `{type: agent}` + 未知类型 fallback 到默认 Agent；
- 配置扩展：`agents.research` 从单值扩展为 `default` + `by_type` map；工作流与证据校验管道不改。

**检索层优化**：
- 同义变体查询（LLM 生成同义词组合）、迭代二轮检索（query-by-example）、LLM 相关性重排；
- 以引用种子集作为已知相关集做 `recall@N` 评测，量化扩展检索质量；
- 引用标题改由 LLM 提取（当前为规则版 best-effort）。

**多源扩展**：
- 接入百度学术（千帆 API）/万方开放平台，`SearchTool` 做多源聚合、document_id 加命名空间前缀（`arxiv:`/`baidu:`）；
- `MetadataTool` 按 DOI（中文文献缺失时按标题归一化 + 年份）跨源去重；
- 中文源为摘要级证据，需与 arXiv 全文级证据分级设门槛。

**其他**：全文章节级 `sections` 切分、全文/检索结果缓存落盘、证据卡来源标记（seed/expansion/fulltext/abstract）以支撑报告 limitations。
