## 本次实现

1. 默认数据库发现阶段只保存摘要，候选上限仍为 8；不再预先下载每批 8 篇全文。
2. 现有 `database_search` 增加 `full_text_source_record_ids`，最多 4 个同库已发现文献句柄。此路径不重新执行检索，不伪造 SearchExecution；通过原数据库 provider 获取、落盘全文，保持数据库来源属性。返回 `full_text_artifact_ids`，随后仍须 Reader 读取才能构建 Evidence。已有全文直接复用，无法取得全文时保留摘要和诊断信息。
3. 全文并发限额从单次检索局部变量改为同一检索工具实例、同一事件循环内共享；同时请求同一 document_id 时合并在途请求。没有改动 arXiv 8 秒物理请求间隔，也没有扩大其重试预算。这不是新建搜索优先级调度器。
4. 格式修复禁用 thinking，HTTP 超时最多 60 秒，仍只允许一次修复，保持原文和语义校验。为避免截断有效证据 JSON，未额外压低原有输出 token 上限。
5. 单卡 Reviewer 每次模型请求的 HTTP 超时受剩余卡片预算约束，并保留外层超时及失败关闭机制。Reviewer 默认单次模型超时改为 90 秒、Extractor 为 120 秒，两者关闭 thinking；汇总仍沿用独立 180 秒预算。
6. Researcher prompt 说明摘要批量阅读及按需全文路径；Reviewer prompt 补充合法状态/裁定字段组合示例。

本次没有实施跨轮评审缓存、失败检索分类缓存或新增模型角色计时字段。原始 Evidence、Reader 和单卡并行后汇总的工作逻辑保留。

## 仍存在的问题与后续方案

### 1. 摘要缺失细节被写成“未采用”：质量问题，尚未解决

本轮 Reviewer 和报告出现“未采用图摘要压缩”“未用 RNN”等否定陈述，但对应证据只有摘要。仅凭摘要未提及，不能证明全文没有这些技术。当前按需全文提示尚不足以让模型自主获取全文。

建议在 Researcher/Reviewer 增加可验证约束：凡以“缺少/未采用某特征”作为区分依据，必须关联能支持该否定的原文；否则表述为“当前已读摘要未提供该特征证据”，保留不确定性。若该特征影响裁定，优先触发按需全文；全文不可得则返回证据不足，不能通过缩短证据链得到过强结论。在补上这一约束前，本轮只能证明性能路径有效，不能证明与全文优先策略质量等同。

### 2. Springer HTTP 404 后重复固定检索

NP-2 的查询 `"distributed graph neural network" AND "graph summarization"` 两次收到 HTTP 404，耗时约 1.335 和 0.674 秒。NP-1 同一 provider 正常返回 8 篇，故不能笼统归因为数据库未配置。日志只能确认特定查询返回 404，不能据此认定零命中。

现有 Harness 只复用完整成功结果，不缓存失败，所以允许原样重复。后续可对同任务、同 provider、同查询的确定性非临时错误设置已失败标记，提示换库或新计划；429/超时则走有上限退避。零命中保持成功且可复用。未经 API 响应体确认，不把 404 改成零命中。

### 3. 批量 Reader 的原生诊断误报

`diagnostics/reference_namespace.json` 报 18 个错误，Reader 诊断报 18 个 INCOMPLETE_RECORD；其解析路径仍按单条读取的顶层 namespace/artifact_id 取值，未展开 `read_results`。本次独立逐片段审计没有发现命名空间、文件或引文不一致。

后续应统一单条/批量结果展开，按片段核验命名空间，单独统计执行前 Harness 拦截与真正 Reader 失败。该问题污染诊断展示，本轮未阻止主工作流或报告生成。

### 4. 仍有无效决策往返

数据库成功结果复用正常（一次 arXiv 调用约 0 毫秒），但再次返回制品会重新触发 Reader 门槛；模型尝试换库或读取非本次要求的制品被拦截。数据库 5 次失败中，3 次为门槛拦截、2 次为 Springer 404。后续可在待阅读状态只暴露 Reader，或显式返回必须读取的候选 ID，同时保持原文读取门槛。

本轮没有发生阻断最终报告生成的异常；上述质量限制和诊断问题仍应保留在评估中。
