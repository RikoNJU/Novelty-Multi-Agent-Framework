# 检索候选到 EvidenceCard 丢失修复

## 根因与修改

1. 原生工具循环耗尽轮次、总调用数、单工具次数或读取字符预算时，原来直接返回 partial，已读取正文未经过 Builder。现在 Researcher 专用开关允许一次禁用工具的最终整理，随后正常构建卡片；仍标记 partial，保留覆盖不完整的事实。其他 harness 使用者默认行为不变。
2. Builder 仍要求引文匹配可信 Reader 原文。现在输出逐条草稿拒绝原因，由模型最多纠正一次，仅纠正被拒绝草稿；纠正结果再次经过原 Builder。无论纠正失败、输出非法或没有恢复卡片，原有有效卡片和证据都会保留。历史 HGP-IC 的 `$$ + $$ +` 被改写问题已纳入回归。
3. 每个任务新增 candidate_audit，并在论文工作目录写 candidate-audit.json，关联候选、正文 artifact、Reader read 和卡片 ID。区分未读、无法取得正文、已读未产卡、任务中断和已产卡，按 namespace 隔离。无证据支持时不会将候选标记为不相关。异常检索载荷不会阻断已有读取结果审计。
4. 提示词根据实际注册工具说明 browser 是否可用；未提供 browser 时，Web 命中只算发现信息，不能把 source_record_id 当作 Reader 的 artifact_id。预算提示放在系统上下文，保持最新工具消息原有顺序，优先读取已发现且可读的候选。

## 验证范围与限制

本次没有重跑三组完整在线实验。上述产卡测试使用脚本化模型响应和实际 Builder、工作流、持久化逻辑，证明恢复路径和边界行为，不代表真实模型必然选中每篇候选。

原计划附加真实模型回放，但自动审批拒绝发送归档 Reader 文本，理由为未识别到具体内容向外部模型的出站授权。已只读核对历史 manifest.egress_authorized=true，且历史与当前模型目的地均为 https://api.siliconflow.cn/v1；未绕过拒绝，也未执行本次在线回放。此项不作为测试通过证据。

每个任务最多增加一次预算整理和一次草稿纠正，即最多两次模型调用；二者禁用工具。检索命中数量与卡片数量不保证相等：重复文献、无可读正文、未读取、未被选作证据和校验失败都可能产生差异。此次修复防止预算直接丢失已读证据，并让剩余差异可追踪；没有实现强制逐篇阅读或强制产卡。
