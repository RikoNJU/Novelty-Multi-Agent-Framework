# 任务书逐项复核：尚未通过整体验收

依据：[原任务书](../../../task/Novelty%20Framework%20Harness%20与配置管理系统审查任务定义.md)。本次复核回应用户“核对任务书，你确定你做完了吗”。

**结论：不能声称整份任务已经完成。已完成的是两轮证据调查、若干限定工程修复和对应测试，任务状态应为“部分完成，尚未通过整体验收”。** 上次用“完成本轮续查”结束工作，未同步逐项说明整体验收差距，属于交付状态表达和任务收尾判断不充分。1,104 项离线测试通过不能替代任务书第 9 节的验收。

本任务是探索审查，不以小模型成功替代强模型为目标。没有接入所有候选 Provider、没有估造 GPU 成本、没有把未知根因编成确定原因，都不是欠缺。调查项可因有证据的 Unknown/访问条件受限而完成；但“仅提出方案”“仅实现局部机制”和“已经验证系统能力”必须分开。

## 5. 本次复核新增的代码边界

以下均为本次只读代码审查发现，尚未新增运行复现或修复。已有1,104项测试未覆盖相应的最终业务断言，不能用这些测试的通过否定缺口。

1. **取消竞态的已知usage未进入总账。** `core/runtime_artifacts.py` 将晚到返回存到 `late_completion`，将完成后取消的结果存到 `transport_completion_before_cancel`；汇总却只读顶层 `tokens/billing`，单条晚到写入也不刷新summary。现有竞态测试检查了旁路保存，没有验证最终usage汇总。因此“失败/取消请求用量均可核对”不能作为已验证结论。
2. **Provider已给usage但响应解析失败时可能遗失。** `backend/env/model_client.py` 收到JSON后事件只记录 `usage_available` 布尔；随后choices/message/tool_calls解析失败会发无ModelResponse的终结错误，raw.usage未进入terminal provider_usage。需要区分“Provider未给用量”与“客户端未保存已给用量”。
3. **Reader工具失败仍可能被归为语义证据不足。** `agents/evidence_reviewer.py` 对合法 `insufficient_evidence` draft 直接赋 `semantic_evidence`，尚未结合工具失败观察判断技术阻塞；异常直接上抛的兜底修复只覆盖一部分路径。
4. **材料不可获取与越权仍可能混淆。** `tools/reader.py` 构造Reviewer材料目录时对文件缺失/hash错误等直接跳过，后续该Artifact可能显示为scope外。应保留不可获取原因，同时保持越权访问拒绝。

这些发现说明缺口不仅是“尚未测出语义能力”，也包括仍可由工程处理的确定性数据流问题。

## 6. 继续闭合的工作顺序与完成证据

1. **统一配置与实验条件。** 先覆盖现有正式入口，而非新增未来模式；将运行前preflight、处理器角色和所有实际覆盖来源对齐。新实验在启动前冻结完整源码状态，运行期间禁止改该实验所用代码。用入口级测试证明坏配置在模型/检索之前停止、合法配置真正到达客户端且与manifest一致。
2. **查新范围与Reviewer。** 建立作者声明/机制特征→候选→合并代表→最终任务的审计账本；对未核实等价的删除保留未决范围。用已有反例和独立材料验证；在有材料、材料不足、技术故障三类输入上验证Reviewer局部事实/裁定，完成汇总失败后的有界恢复。不能用点数、有效JSON或引文存在冒充语义覆盖。
3. **错误、用量与恢复。** 先复现并修补上节取消/解析用量及Reader原因丢失，再将现有草案补成字段约束、代码目录和生产映射，覆盖任务书列出的故障类别；用同一输入仅改变故障注入点，证明retry/换源/补读/补检/仅重汇总/停止的区别及预算边界。按可确认事实决定动作，不从模型自然语言“预算不足”推导真实预算。
4. **Context与端到端验证。** 验证选定的长轨迹状态投影/任务分段或明确可恢复停止方案，保留原始provenance；固定输入与预算做独立重复对照。 arXiv故障需继续有界定位；未恢复前可用明确标注的本地原始文献回放验收下游，不能伪称在线检索已恢复。

并非要求所有未知原因都查明、所有小模型输出都正确才允许结束探索任务。最终应交付逐条证据、选定方案的有界验证、尚未知问题的实验边界与理由；当前尚缺以上核心闭合证据，因此不能仅凭测试数量或一次流程完成宣布总任务结束。
