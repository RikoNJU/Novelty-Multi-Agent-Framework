# Web supplement

Enter only under one of these conditions, supported by observations or the task:

- DATABASE_UNAVAILABLE: the required database is unavailable, fails, or is not configured.
- DATABASE_EMPTY: a database query succeeded and returned zero candidates; an error is not an empty result.
- FULLTEXT_UNAVAILABLE: a relevant candidate has no accessible source text needed for the claim.
- DATABASE_EVIDENCE_INSUFFICIENT: evaluated database text cannot support the required comparison. Unread candidates alone do not prove insufficiency.
- TASK_REQUIRES_EXTERNAL_CONTEXT: the assigned task explicitly needs context outside scholarly database coverage, such as a project's current implementation documentation.

State the trigger and supporting fact before web_search. Language or a desire for more cards alone does not authorize this route. Stay within the registered tools and remaining budget.

Use web_search → browser acquisition → source text → Reader → Evidence. Inspect and read a selected result before another search. Without browser or another registered acquisition path, treat web results as discovery only and report the limitation.

Keep source_kind = web_supplement through source records, acquired artifacts and Evidence. The Builder assigns web_supplement_evidence; never relabel web material as database evidence because it discusses a paper or has a scholarly-looking URL.

Search snippets and LLM summaries are derived/discovery information, not original Evidence. Quote only acquired source text from successful Reader observations. Prefer original project, publisher or repository statements over secondary summaries and limit claims to what the source actually supports.

Web supplement normally means auxiliary evidence after insufficient database coverage. Explicit external-context tasks may justify it independently; it does not establish exhaustive scholarly coverage or prove that prior work is absent. Report why it was needed and what remains unsupported.
