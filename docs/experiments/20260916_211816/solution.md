## 覆盖与质量边界

B 的 6 张卡覆盖三个查新点，A 的第三点证据不足；不过两轮的第三点**内容不同**。A 的 NP-3 重复拆出 GSAERU 与性能指标，B 在提取器提示词约束下把边分割图流划分作为独立查新点。这个差异使卡片数和第二轮 Research 耗时不能只归因于全文机制或提示词。B 对 NP-2 给出 `novel`，A 给出 `partially_novel`；没有外部人工真值，不能据此宣布某个裁定更准确。

Springer 在 A 返回了 8 条记录；B 的 6 次实际 Springer 检索都收到 HTTP 404，因此没有 Springer 候选。虽然服务配置一致，两轮实际检索语句和响应并不一致。两轮 WebSearch 都可调用，但 Browser 实际调用均为 0，不能把它视为浏览能力实测。

独立核验最终 Evidence：A 的 4 条引文都与制品原文逐字相同；B 的 8 条中 5 条逐字相同，另外 3 条位于同一篇 PDF 提取全文，模型把原文换行归一成空格。现有 Evidence 构建与完整性门槛允许空白归一后匹配，因此原生校验通过；若报告要求引文逐字复制，应保存定位处的原始文本片段，而不是模型归一后的引文。这是现有证据链的质量限制，不能因为报告生成成功而忽略。

## 判断与建议

1. **批量全文是明显的等待来源。** 20:40 的原提示词按需实验仅 3 次 arXiv 物理搜索、耗时 137.8 秒；A 恢复批量全文后有 37 次物理请求、耗时 576.6 秒。两次生成的查新点和轮次不同，439 秒差值不能全归为全文下载，但 8 秒请求间隔与研究阶段等待直接可见。
2. **只改提示词不足以同时解决耗时与证据覆盖。** B 虽覆盖三个点，耗时更长，且内部推理 token 大幅增加。提示词能影响拆点和阅读选择，不能替代 API 层的推理开关、超时预算或有界全文调度。
3. **下一版适合组合验证。** 保留按需全文路径及共享请求限额；给相关性最高的少量候选预取全文，摘要不足以支撑“未采用”之类否定时强制按需获取或标记证据不足；保留 B 的独立贡献拆点约束和 Reviewer 的合法 JSON 示例，同时维持明确的模型参数约束。随后固定查新点输入再重复对照，才能隔离速度与质量的因果关系。
